# What is IncidentFlow MCP

> Contract version: `0.1.0` · Release status: candidate · Human documentation review: pending

> **TL;DR**  
> IncidentFlow MCP is an MCP-compatible incident intelligence platform for AI-powered SRE workflows.

IncidentFlow MCP is an MCP-compatible service designed to make incident context accessible to AI systems in a structured and actionable way.

The current tool surface connects AI agents to:

- IncidentFlow incident summaries and alert correlation
- approved Slack incident channels and threads
- connected Kubernetes clusters through the read-only agent
- public provider-status pages through `external_status_check`

`external_status_check` does not connect a customer's GitHub account or repositories. IncidentFlow
does not currently advertise a customer GitHub integration.

Instead of unbounded raw data, IncidentFlow provides:

- normalized signals
- correlated events
- incident context
- historical patterns

This allows AI agents to answer questions like:

> Has this incident happened before?
>
> What was the root cause last time?
>
> What actions usually fix this?

## Why MCP?

Model Context Protocol (MCP) enables AI systems to:

- discover tools dynamically
- access structured data
- execute actions safely

IncidentFlow MCP exposes operational intelligence via MCP so that AI agents can:

- query incident history
- analyze real-time signals
- assist SRE workflows
- automate diagnostics

## Key capabilities

- Incident summaries and alert correlation
- Read-only Slack and Kubernetes investigation
- Public provider-status lookup
- MCP interface for AI agents

Incident memory and Grafana entries exist in source-level contract work but are not accepted public
capabilities. Check the [tool catalog](../reference/tool-catalog.mdx) and the deployed `tools/list`
result before relying on a capability.
